# Termly: แผนงาน MVP

เวอร์ชันแรกโฟกัส "เรื่องงาน/Deadline" เท่านั้น
เวลาที่มี: ประมาณ 1-2 ชม./วัน, 4 วัน/สัปดาห์ รวม 3 สัปดาห์ (12 เซสชัน)

## แนวคิดหลัก

นักศึกษาวางข้อความ / อัปโหลด PDF / แคปรูป (ซิลลาบัส, ประกาศ, กำหนดการ)
AI ดึงข้อมูลออกมาเป็นรายการ → ผู้ใช้ตรวจและแก้ → บันทึกเป็นแผน → ดูเป็นรายสัปดาห์ → ส่งออกลง Google Calendar

หลักการที่ล็อกไว้:
- ไม่ต้องใส่คะแนนรายงานแต่ละชิ้น (อาจเปลี่ยน/มีงานเพิ่ม)
- สัดส่วนคะแนน: ล็อกเฉพาะ Midterm / Final (แก้วันสอบได้) ส่วนที่เหลือเป็นก้อน "งานเก็บคะแนน" ปรับเองได้ (ทำในเฟส 2)
- ต้องมีหน้า "ตรวจก่อนบันทึก" เสมอ เพราะ AI อ่านพลาดได้

## แผนรายวัน (ตามลำดับเซสชัน)

### สัปดาห์ที่ 1: ฐานระบบ + ดึงข้อมูลได้

| เซสชัน | งาน | ผลลัพธ์ที่ต้องได้ |
|---|---|---|
| 1 | ตั้งโปรเจกต์ Next.js, Tailwind, deploy ขึ้น Vercel ตั้งแต่วันแรก | มีลิงก์เว็บเปิดได้ |
| 2 | ตั้ง Supabase + ล็อกอินด้วย Google | ล็อกอิน/ออกได้ |
| 3 | ออกแบบตาราง: courses, tasks, events + RLS ให้เห็นเฉพาะของตัวเอง | เพิ่ม/ดู/แก้/ลบ task ด้วยมือได้ |
| 4 | หน้าเพิ่มวิชา + หน้ารายการงาน (เรียงตามวัน) | ใช้เป็น to-do ธรรมดาได้แล้ว |

### สัปดาห์ที่ 2: ส่วนแกนของแอป (AI)

| เซสชัน | งาน | ผลลัพธ์ที่ต้องได้ |
|---|---|---|
| 5 | หน้า "วางข้อความ" → เรียก AI → ได้ JSON รายการงาน (ชื่อ, วิชา, วันส่ง, หมายเหตุ) | ทดสอบกับซิลลาบัสจริง 3 วิชา |
| 6 | หน้า "ตรวจก่อนบันทึก": แก้ชื่อ/วันที่ได้, ติ๊กเลือก/ลบรายการ, เตือนถ้าวันที่ไม่ชัด | บันทึกลงฐานข้อมูลได้ |
| 7 | รองรับอัปโหลด PDF และรูป (แคปหน้าจอ) | PDF ภาษาไทย/อังกฤษอ่านได้ |
| 8 | จำกัดการใช้ AI ต่อคนต่อวัน + จัดการ error (AI ตอบผิดรูปแบบ, ไฟล์ใหญ่เกิน) | ไม่มีทางสแปมจนค่า AI บาน |

### สัปดาห์ที่ 3: ใช้งานจริง + เปิดให้คนลอง

| เซสชัน | งาน | ผลลัพธ์ที่ต้องได้ |
|---|---|---|
| 9 | มุมมองรายสัปดาห์ (สัปดาห์ไหนงานหนัก) + ทำ PWA ให้ติดตั้งมือถือได้ | ใช้บนมือถือลื่น |
| 10 | ส่งออกไฟล์ .ics ลง Google Calendar | งานขึ้นในปฏิทินจริง |
| 11 | ปรับ UI ให้เรียบ minimal + หน้าแรกอธิบายสั้น ๆ + ทดสอบกับตัวเอง 1 เทอมจริง | ไม่มีบั๊กใหญ่ |
| 12 | เปิดให้เพื่อน 5-10 คนลอง + แบบฟอร์มความเห็น + ตั้งราคาทดลอง | ได้ฟีดแบ็กและสัญญาณว่ามีคนยอมจ่ายไหม |

### เฟส 2 (หลังได้สัญญาณจากผู้ใช้จริง)
- ส่วนสัดส่วนคะแนน + เครื่องคำนวณ "ไฟนอลต้องได้เท่าไหร่ถึงได้เกรดที่ต้องการ"
- ส่วนกิจกรรม (วางกำหนดการ/PDF แยกเวลา สถานที่)
- ระบบชำระเงิน / แพ็กเกจพรีเมียม

## ข้อควรทำทุกเซสชัน

1. เปิดเซสชันด้วยการบอก agent ว่า "วันนี้ทำเป้าหมายข้อ X" และให้ใช้ไฟล์ CLAUDE.md เป็นบริบทหลัก
2. จบเซสชันด้วยการ commit และให้ agent สรุปว่าเสร็จอะไร ค้างอะไร
3. อ่านโค้ดที่ agent เขียนคร่าว ๆ โดยเฉพาะส่วนล็อกอิน, ฐานข้อมูล, และ API key
4. ทดสอบด้วยข้อมูลจริงของตัวเองเสมอ

## รายละเอียดเพิ่มของบางเซสชัน

**เซสชันที่ 5:** หน้าวางข้อความซิลลาบัส เรียก AI ฝั่งเซิร์ฟเวอร์ คืน JSON ตาม schema (title, course, due_date, due_date_confidence, note) ถ้าวันที่ไม่ชัดให้ confidence = low แทนการเดา เขียนชุดทดสอบด้วยข้อความตัวอย่างภาษาไทย 3 แบบ

**เซสชันที่ 6:** แสดงรายการที่ AI ดึงมาเป็นการ์ด แก้ชื่อ/วันที่ได้ ติ๊กเลือกหรือลบได้ ไฮไลต์รายการที่ confidence ต่ำเป็นสีเหลือง มีปุ่มบันทึกทั้งหมด
